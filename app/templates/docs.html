步骤流

从拿到密钥到正式接入

先跑通最短链路，再扩展到具体客户端和具体能力。不要一上来就从最长请求开始排查。

1

拿到平台 API Key

从管理员或用户侧密钥控制台获取平台 API Key。外部请求统一使用平台密钥，不直接暴露后台调试接口。

2

复制 Base URL 和正式入口

把 OpenAI 兼容入口设为 {{ external_v1_base_url }}。正式只使用当前已支持的 /v1/* 路径，不把后台页地址或 playground 地址当成对外接口。

3

先跑一条最短请求

优先调用 /v1/models 或一条最短文本请求，验证鉴权、模型可见性和路由链路是否都已经跑通。

4

按客户端类型填配置

支持 OpenAI 兼容 Base URL 的客户端，统一按 Base URL、API Key 和模型名三项配置；模型名以 /v1/models 返回结果为准。

5

图片生成优先走 Responses

正式推荐 POST {{ external_v1_base_url }}/responses + tools=[{"type":"image_generation"}]。旧版 /v1/images/* 只作为兼容层保留。

生图流

官方 Responses 生图工作流

正式推荐路径优先展示，旧版 Images API 兼容细节后置展开，避免把用户带进低频兼容分支。

先记住这一条

正式推荐路径

本平台当前正式兼容的是 OpenAI 官方 Responses + image_generation 工作流。客户端统一使用 {{ external_v1_base_url }}，图片生成和图片编辑都优先发到 /v1/responses。

  • 外层 model 选择可路由的 Responses 模型
  • 工具层显式写 {"type":"image_generation","model":"gpt-image-2"}
  • 编辑图时再补 "action":"edit"，并把源图放进 input
官方示例

文生图 · 非流式

适合直接一次性拿最终图片。

curl {{ external_v1_base_url }}/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_PLATFORM_API_KEY" \
  -d '{
    "model": "gpt-5.4",
    "input": "生成一张极简风格的蓝色纸鸢图标，白底，单主体",
    "tools": [
      {
        "type": "image_generation",
        "model": "gpt-image-2",
        "action": "generate",
        "background": "opaque",
        "output_format": "png",
        "size": "1024x1024",
        "quality": "high"
      }
    ],
    "tool_choice": {"type": "image_generation"}
  }'

成功响应里重点看 output 数组中的 image_generation_call；最终图片通常在 item.result。

官方示例

文生图 · 流式

适合监听中间事件和最终产物。

curl {{ external_v1_base_url }}/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_PLATFORM_API_KEY" \
  -N \
  -d '{
    "model": "gpt-5.4",
    "stream": true,
    "input": "生成一张暖色调的产品海报背景，不要文字",
    "tools": [
      {
        "type": "image_generation",
        "model": "gpt-image-2",
        "action": "auto",
        "output_format": "png"
      }
    ],
    "tool_choice": {"type": "image_generation"}
  }'

优先监听 response.output_item.done；若 item.type == "image_generation_call" 且 item.result 存在，即说明拿到了最终图片。

官方示例

图片编辑 · Responses

编辑图不要切回旧版 Images API。

curl {{ external_v1_base_url }}/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_PLATFORM_API_KEY" \
  -d '{
    "model": "gpt-5.4",
    "input": [
      {
        "role": "user",
        "content": [

          {"type": "input_image", "image_url": "data:image/png;base64,REPLACE_WITH_BASE64"}

      }
    ],
    "tools": [
      {
        "type": "image_generation",
        "model": "gpt-image-2",
        "action": "edit",
        "output_format": "png",
        "quality": "high"
      }

    "tool_choice": {"type": "image_generation"}
  }'

源图作为 input_image 放进 /v1/responses，并把工具动作固定成 edit 即可。

展开旧客户端兼容流
兼容层

images/generations

旧客户端文生图兼容入口。

curl {{ external_v1_base_url }}/images/generations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_PLATFORM_API_KEY" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "生成一张极简风格的蓝色纸鸢图标，白底，单主体",
    "response_format": "b64_json"
  }'

内部会自动改写成 /v1/responses + image_generation，但正式推荐口径仍然是 /v1/responses。

兼容层

images/edits

旧版编辑图兼容入口。

curl {{ external_v1_base_url }}/images/edits \
  -H "Authorization: Bearer YOUR_PLATFORM_API_KEY" \
  -F "model=gpt-image-2" \
  -F "prompt=只修改背景，把背景换成干净的浅灰摄影棚，主体不要变化" \
  -F "response_format=b64_json" \
  -F "image=@/path/to/source.png"

支持 multipart/form-data，也兼容 JSON 里直接传 data URL。

兼容层

images/variations

相近变体的旧式兼容入口。

curl {{ external_v1_base_url }}/images/variations \
  -H "Authorization: Bearer YOUR_PLATFORM_API_KEY" \
  -F "model=gpt-image-2" \
  -F "response_format=b64_json" \
  -F "image=@/path/to/source.png"

语义上仍属于兼容适配，不应替代你在 /v1/responses 里显式控制的正式做法。

兼容细节

response_format=url

旧版 Images API 的 URL 返回值说明。

当旧版 Images API 请求使用 response_format=url 时，平台当前返回的是 data:image/...;base64,... 形式的 data URL 兼容值，而不是临时 CDN 文件地址。

如果你的客户端需要真实可下载的公网 URL，请优先自己把返回图片保存到对象存储，或直接走 /v1/responses 后自行落地文件。

SDK 示例

OpenAI Python SDK

适合支持 Responses 的 Python 客户端。

from openai import OpenAI

client = OpenAI(
    base_url="{{ external_v1_base_url }}",
    api_key="YOUR_PLATFORM_API_KEY",
)

resp = client.responses.create(
    model="gpt-5.4",
    input="生成一张极简风格的蓝色纸鸢图标，白底，单主体",
    tools=[
        {
            "type": "image_generation",
            "model": "gpt-image-2",
            "action": "generate",
            "output_format": "png",
        }
    ],
    tool_choice={"type": "image_generation"},
)

for item in resp.output:
    if getattr(item, "type", None) == "image_generation_call" and getattr(item, "result", None):
        image_base64 = item.result
        break
错误返回

外部请求一定返回可读结果

正常返回正常响应，失败返回结构化错误。接入时优先保留错误码、说明和 trace_id。

错误体

JSON 请求错误体

失败请求会返回可读错误结构。

{
  "error": {
    "message": "具体错误说明",
    "type": "server_error",
    "code": "upstream_request_failed",
    "trace_id": "请求追踪 ID",
    "retryable": true
  }
}
SSE

流式请求错误事件

SSE 建立后出错，会发 error 事件并以 DONE 收尾。

event: error
data: {"error":{"message":"具体错误说明","code":"stream_interrupted"}}

data: [DONE]
能力校验

端点能力错误

模型或渠道没有原生支持所请求入口时返回。

{
  "error": {
    "message": "No available provider for requested model",
    "code": "model_not_available",
    "detail": {
      "requires_tools": true,
      "route_diagnostics": {"summary": "没有满足原生端点能力的候选"}
    }
  }
}
